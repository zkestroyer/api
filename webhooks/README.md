# Student Management System Webhooks

A complete webhook implementation for a Student Management System using Express.js and Axios. 

**Author:** Zainab Khan

## Webhook Architecture

This project consists of two separate microservices:

1. **Sender Service (Port 3004)**: A RESTful API for managing students. It acts as the webhook provider, allowing consumers to register endpoints and dispatching events when student records are created, updated, or deleted.
2. **Receiver Service (Port 3005)**: A sample consumer application that registers for webhooks and listens for incoming payloads, verifying their authenticity using an HMAC-SHA256 signature.

## Features

- Complete OOP design with ES6 Classes and Modules
- Model-Repository-Service-Controller architecture
- In-memory data persistence
- HMAC-SHA256 signature generation and verification for webhook security
- Webhook dispatching with exponential backoff retry logic (up to 3 attempts)
- Full JSDoc documentation for all classes and methods

## Event Types

The sender service emits the following events:
- `student.created` - Fired when a new student is added
- `student.updated` - Fired when an existing student is modified
- `student.deleted` - Fired when a student is removed

## Payload Format Example

When a webhook is triggered, the receiver gets a POST request with a JSON body like this:

```json
{
  "event": "student.created",
  "timestamp": "2026-08-01T15:10:00.000Z",
  "data": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "name": "Ali Khan",
    "email": "ali@example.com",
    "course": "Physics",
    "year": 1,
    "gpa": 3.8
  }
}
```

## HMAC Signature Verification

To ensure webhooks are coming from the trusted sender and haven't been tampered with, the sender includes an `X-Webhook-Signature` header in every dispatch attempt.

This signature is generated by computing an HMAC-SHA256 hash of the raw JSON payload body using a shared secret key (`webhook-secret-key-2026`). 

The receiver computes the same hash using the incoming raw payload body and its copy of the secret key. If the computed hash matches the `X-Webhook-Signature` header, the request is authenticated.

## Testing the Flow

1. **Start both services** (`npm start`)

2. **Register the Receiver's Webhook URL**
   Make a POST request to `http://localhost:3004/api/webhooks/register`:
   ```json
   {
     "url": "http://localhost:3005/webhooks/student-events",
     "events": ["student.created", "student.updated", "student.deleted"]
   }
   ```

3. **Trigger an Event (Create a Student)**
   Make a POST request to `http://localhost:3004/api/students`:
   ```json
   {
     "name": "Jane Doe",
     "email": "jane.doe@university.edu",
     "course": "Mathematics",
     "year": 2,
     "gpa": 3.9
   }
   ```

4. **Observe the Result**
   - The Sender terminal will log that it dispatched the webhook.
   - The Receiver terminal will log that it successfully received and verified the event.
